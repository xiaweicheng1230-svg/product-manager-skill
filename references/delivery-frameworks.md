# 项目交付与管理文档框架

## 会议纪要

1. 会议名称、日期、参会人、主持和记录人。
2. 会议目标和需要决策的问题。
3. 讨论摘要：保留不同意见和依据，不逐字记录无关对话。
4. 已确认结论：使用明确句子，不把建议写成决定。
5. 待确认问题：责任人、所需输入和截止时间。
6. 行动项：事项、负责人、协作人、交付物、截止时间和完成标准。
7. 风险和依赖。
8. 关联文档及需要更新的章节。

会后根据结论更新正式需求，不让关键决定只停留在纪要中。

## 排期与甘特图

1. 里程碑和对外承诺。
2. 工作分解：产品、设计、客户端、后端、设备、算法、硬件、采购、测试和合规。
3. 每项任务的负责人、开始、结束、工期、状态和交付物。
4. 前置依赖、并行关系和关键路径。
5. 评审、样机、联调、测试、试产、发布和复盘节点。
6. 风险缓冲和变化记录。

排期不能把“开始开发”当交付物。每个节点必须有可检查的输出和通过条件。

## 周报或阶段报告

1. 本期目标和结论。
2. 已完成：只写可验证成果和链接。
3. 进行中：当前状态、下一步和预计完成时间。
4. 问题、风险、影响和需要的支持。
5. 下期计划。
6. 关键数字和版本变化。

## 需求评审清单

- 用户、场景、目标和非目标是否明确；
- 功能、流程、状态、权限、数据和异常是否闭环；
- 硬件、软件、平台和算法能力是否一致；
- 是否存在无法验收的模糊描述；
- 隐私、安全、合规和儿童保护是否覆盖；
- 依赖、成本、排期和待确认问题是否有人负责；
- 原型、需求、接口和测试用例能否互相追踪。

## 验收文档

1. 验收范围、版本、环境、设备和前置数据。
2. 端到端核心场景。
3. 每项需求的正常、异常、离线、权限和边界用例。
4. 性能、可靠性、兼容、安全、隐私和恢复测试。
5. 通过条件、阻断问题、允许遗留问题和责任人。
6. 验收证据：截图、日志、数据、样机编号和测试报告。
7. 结论、限制、上线或进入下一阶段的条件。
